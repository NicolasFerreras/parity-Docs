# Parity — Purchase Order Standardization, Formatting and Matching

<Tip>
Integrator Project — **Scalable system for distributors** (initial case: food distribution, anonymized). Stack `Go + PostgreSQL + React + TypeScript` · HTTP API · Docker. Sensitive data: `lista_articulos.xlsx` never used in production, only fixtures in `testdata/`.
</Tip>

## Purpose

Parity automates the cycle **Excel → validation → catalog matching → human review → persistence** for purchase orders that are currently processed manually. It removes retyping, reduces code and quantity errors, and leaves traceability `R → US → TC`.

## Stakeholders

| Role | Need | Evidence |
|------|------|----------|
| **Operator (employee)** | Upload Excel and correct only the ambiguous rows | Interviews `docs/01-research` |
| **Supervisor / Admin** | Traceability and audit `R→US→TC` | `docs/03-requirements` |
| **Client company (distributor)** | Real catalog data, without filtering | `lista_articulos.xlsx` fixture only §13 |

## MVP Scope

<Steps>
  <Step title="Upload & Excel parsing">
    Handler `cmd/server` → `internal/parser` (excelize, 10MB limit) → `internal/orders`
  </Step>
  <Step title="Validation">
    Header + lines, ghost rows, variant headers, decimals
  </Step>
  <Step title="Matching">
    `internal/matching/normalize.go` → `barcode.go` → `description.go` → scorer → states `exact/ambiguous/failed`
  </Step>
  <Step title="Review & manual editing">
    `src/features/matching` — table with badges, edit modal
  </Step>
  <Step title="Persistence">
    PostgreSQL `migrations/*` — `orders`, `order_lines`, `articles`
  </Step>
</Steps>

## Out of Scope (MVP)

<Warning>
Do not include without `Problem → Requirement → Need → Alternatives → Decision → Technology` and Human Gate.
</Warning>

- Queues / async (RabbitMQ), microservices, Kubernetes, Redis/caching
- WhatsApp blurry photo OCR (PP4b) — ask for resend
- Complex auth / multi-tenant
- Real `lista_articulos.xlsx` in production — always fixture

## Stack and Conventions

| Layer | Stack | Pattern |
|-------|-------|---------|
| Backend | Go 1.22, `excelize` | Handler → Service → Repository, errors `%w` |
| DB | PostgreSQL 16 | Versioned migrations |
| Frontend | React + TypeScript | `src/api/types.ts` typed contract |
| Infra | Docker Compose, GitHub Actions | `docker`/`ci-cd` |

## Non-Negotiable Principles

<Card title="Human Gate (§4)" icon="shield-check">
No agent writes/modifies, commits, pushes, deletes, moves to Done, changes MVP, installs a dependency or decides under ambiguity without explicit confirmation via `question`.
</Card>

<Card title="Plan Mode (§5)" icon="file-check">
Before building/modifying/executing anything, brief plan: what / what NOT / files / risks / reversibility → wait for `approved`. The agent may **suggest** plan mode if needed, never decide for the user.
</Card>

<Card title="Branches and Data (§13-§14)" icon="git-branch">
Own branch, never `main` directly. Tests against fixture DB. `git pull --rebase origin main` before merge, serialize merges, never `--force`.
</Card>
