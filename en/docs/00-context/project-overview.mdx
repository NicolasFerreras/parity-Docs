# Parity Documentation

Parity is a product for standardizing, formatting and validating purchase orders with as little friction as possible. The system combines a processing platform, a product catalog and a review interface that turns messy orders —Excel, PDF or text— into data ready to import.

This documentation is written for product, operations and engineering. It explains what Parity is trying to solve, how the core flows work, and how the technical system supports those flows.

## What Parity Does

Parity helps sales and administration teams to:

* Import orders without retyping — from Excel, PDF or copied text.
* Validate structure, quantities and codes against the catalog.
* Resolve exact matching by code or barcode, and flag the ambiguous for human review.
* Review in a familiar table, edit failures and export in one click to the internal format.

## Main System Components

| Component | Purpose |
| --- | --- |
| Processing platform | Orchestrates validation, matching and order persistence. |
| Catalog | Source of truth for products, codes and barcodes. |
| Review interface | Web client to upload, review and correct orders. |
| API | HTTP contracts for ingestion and queries. |
| PostgreSQL | Durable source of orders and catalog. |
| Docker | Consistent packaging and execution across environments. |
| Mintlify | Documentation hosting and rendering. |

## Current Stage

Parity is in an MVP foundation phase. The architecture is intentionally simple: a Go API, a React frontend and a PostgreSQL database, all orchestrated with Docker. The goal is to validate the complete flow —from messy Excel to validated order in seconds— before introducing asynchronous processing or heavier infrastructure.
